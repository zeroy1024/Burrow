# 数据与凭据

## macOS 数据位置

应用标识为 `dev.burrow.app`，文件位置由 MyGo 的应用路径接口提供。默认路径为：

| 用途 | 路径 |
|---|---|
| 配置、工作区、任务及托管密钥 | `~/Library/Application Support/Burrow/` |
| 缓存 | `~/Library/Caches/Burrow/` |
| 日志 | `~/Library/Logs/Burrow/` |
| 保存的密码与私钥口令 | 系统钥匙串，按应用标识隔离 |

## 数据文件

以下文件和目录位于应用用户数据目录；对应功能使用后才可能生成。

| 文件 / 目录 | 内容 |
|---|---|
| `sessions.json` | SSH/文件目录、托管密钥元数据和工作区快照 |
| `prefs.json` | 应用偏好、快捷键和设置状态 |
| `files.json` | 文件页面偏好 |
| `terminal.json` | 终端配色、字体、光标与背景配置 |
| `themes/` | 导入的 Ghostty 配色文件 |
| `keys/` | 托管私钥文件，创建权限为 `0600` |
| `known_hosts` | 应用独立的 SSH 主机信任记录 |
| `transfers.json` | 正常退出时保存的传输检查点 |

当前 `sessions.json` 外层格式为 v1，其中工作区快照为 v2；传输队列格式为 v4。队列保存所属文件标签、端点/跳板快照、冲突策略、递归清单、提交状态、已确认偏移和 SHA-256 摘要，不保存文件内容。

任务中的 `.part` 文件位于实际传输目标一侧，不在上述队列文件内。只备份配置不能备份这些未完成文件。

## 凭据与主机信任

密码与私钥口令不写入配置 JSON。密码记录带版本，保证旧任务不会把新保存的密码发送给旧端点；版本不匹配时需要重新提供凭据。

外部私钥导入后复制到 `keys/`，原文件不移动。托管目录包含真实私钥，应与钥匙串一起考虑访问权限和备份范围。

未知主机在认证前请求指纹确认；已变更或撤销的主机密钥拒绝连接。测试连接与正式连接使用同一信任规则及应用自己的 `known_hosts`，不依赖终端中其他 SSH 客户端的信任状态。

## 旧数据与备份

当前版本不再读取或自动迁移旧 `~/Library/Application Support/SSH Desk/`，也不会删除该旧目录。旧 `dev.sshdesk.app` 钥匙串命名空间中的密码与私钥口令需要重新录入。

当前 Burrow 数据目录内的 `catalog.json` v0/v2，仅在 `sessions.json` 不存在时迁移，保留源文件和备份。需要解锁的旧加密 PEM 会在窗口就绪后请求口令；取消或失败保留源数据，成功前不会发布不完整目录。

备份前正常退出应用，再复制 Burrow 用户数据目录。系统钥匙串不包含在目录副本中，恢复到其他设备时可能需要重新提供密码或私钥口令。配置中包含站点地址、用户名和本地路径，也应按私有数据处理。

配置读取失败时，应用会报告错误并阻止用默认值覆盖原文件；保存失败也会明确提示。传输恢复行为见[文件管理与传输](file-transfer.md)。

# SFTP 与 FTP 基础连接

文件页已接入真实 SFTP / FTP 登录与远程目录只读浏览。SSH 主机与文件站点使用两套独立目录，连接快照与界面视图分开管理；同一 SSH 连接可以承载独立 Shell 与 SFTP 子系统。上传、下载、文件修改、本地文件面板和传输调度留在后续阶段。

## 目录与身份

`catalog.json` v2 包含 `ssh` 和 `files` 两套数据，各自保存条目、分组、排序、折叠及后续 ID 计数。ID 在所属目录内稳定，删除后不重编号、不复用；两个目录中的相同整数 ID 不代表同一个主机或站点。目录组件复用原有原生列表，但当前页显式绑定自己的目录。

旧共享目录第一次加载时复制为两个独立副本：SSH 使用旧 `collapsed`，文件使用旧 `files_collapsed`，后续新增、编辑和删除互不传播。原目录备份为 `catalog.json.v1.bak`；存在的旧文件偏好备份为 `files.json.v1.bak`。旧地址键对应的本地路径偏好一次性导入 `files.local_paths` 并绑定稳定站点 ID，原 `files.json` 保留全局界面偏好。成功迁移会提示用户，v2 后续加载不重复导入；校验、备份或写入失败时保护原配置。

每个运行会话保留建立连接时的名称、地址、账号、端口和认证来源快照。编辑或删除保存记录只修改目录元数据；存活 SSH / 文件会话仍使用自己的快照，直到用户关闭。临时快捷视图只存在于运行期，不自动添加到保存目录。

## 连接与生命周期

| 协议或动作 | 当前行为 |
| --- | --- |
| 独立打开 SFTP 站点 | 建立该站点的 SSH 认证连接，再申请 `sftp` 子系统，不申请 PTY |
| 从 SSH 打开文件会话 | 在当前已认证连接上创建 SFTP 通道，或激活同连接的已有文件视图 |
| 从 SFTP 打开 SSH | 返回对应的存活 Shell，或在同连接上创建独立 Shell / PTY |
| 同会话 SSH 分屏 | 共享底层连接和认证，每窗格独立 Shell、输入输出、工作目录和尺寸 |
| 普通 FTP | 独立登录，使用控制连接和被动数据连接；不共用 SSH 的 TCP 或认证 |
| 关闭 / 断开一个视图 | 关闭自身通道或 FTP 会话，释放自己的引用；其他健康 SSH / SFTP 消费者继续使用共享连接 |
| 最后一个共享连接使用者结束 | 关闭底层 TCP；已取消的内部等待不单独保活 |

普通页面或标签切换不自动连接；侧栏双击 / Enter、明确重连和快捷按钮才发起所需连接。普通激活一个已断开的文件标签只展示其状态，显式快捷打开已关联但断开的目标可以重连。

共享 SSH 连接仍健康时，结束的 Shell 可直接重新申请通道，不重复认证；连接已关闭后再次明确连接才重新进行认证。密码与私钥口令按需输入，不落盘。主机密钥沿用应用专属 `known_hosts` 的首次确认与变化拒绝规则。

### 快捷关联

快捷入口在来源会话已连接时启用。

SSH 通过「打开文件会话」优先进入已有文件快捷关联；没有关联时打开同连接的 SFTP。SFTP 文件页通过「打开 SSH 会话」返回同组 Shell。新建目标是临时标签；重复点击优先激活已有运行视图并保留其状态。Shell 当前目录与文件页目录不自动同步。

普通 FTP 的 SSH 入口首次要求明确选择已保存 SSH 主机，再关联当前运行中的目标视图。之后通过按钮复用该关联；目标已关闭时按原快照建立所需视图。这是本次运行会话的关联，不是保存目录中的永久默认目标。FTP 账号可能是虚拟用户，程序不会猜测它对应的 SSH 账号、端口或密码，也不会把 SSH 临时密码提交给 FTP。

## 远程目录只读浏览

连接成功后先取得协议返回的初始目录，再读取真实目录项；界面不填充演示文件或虚构进度。可用操作包括进入文件夹、上级、前后历史、面包屑、刷新、名称搜索、排序、选择和复制路径。文件预览与下载尚未开放。

目录读取成功后才提交目标路径、历史位置和内容。权限不足、目录不存在或协议错误显示具体错误，保留原成功目录；空列表只有在真实读取成功后才作为空目录展示。同一文件视图一次执行一个目录请求，快速导航时只提交最新目标，旧响应不会覆盖新目录。

正在连接时可以取消；断开和失败显示重连入口。断开、关闭标签和退出应用会取消相应任务、释放协议资源。SFTP 目录操作取消或超时时释放该文件子系统；普通 FTP 执行中的操作取消或超时会结束该 FTP 会话，重新使用需要明确重连。其他共享 Shell 不因单个 SFTP 视图结束而断开。

### 当前界面边界

- 本地抽屉强制收起且入口禁用，旧本地路径偏好仍保留为站点元数据，不执行本地文件读写。
- 上传、下载、新建目录、重命名、删除和拖放传输入口禁用，或显示「暂未开放」说明；不会通过内存目录修改或假任务完成模拟成功。
- 底部传输面板保留布局与偏好，但不调度任务。遗留运行、排队或暂停状态会明确转为未开放失败，速度保持为零。
- 侧栏、面包屑、搜索、表格和主题继续沿用原生控件及 token；本轮不进行新版 UI 的视觉重做。

## 协议适配与限制

SFTP 使用 `github.com/pkg/sftp v1.13.12`，通过指定 SSH 连接的二进制子系统流初始化。该流的 stderr 单独排出，不混入 SFTP 协议字节；关闭客户端只释放所属子通道。目录项提供名称、大小、时间、目录类型和可用权限，所有者使用服务端返回的数字 UID / GID。

普通 FTP 使用 `github.com/jlaffaye/ftp v0.2.4`。登录凭据与数据在普通 FTP 协议中为明文；被动数据连接使用已解析控制连接的对端，不信任 PASV 响应给出的任意地址。用户、密码与路径拒绝 CR、LF 和 NUL，畸形 PWD 响应作为失败处理。

FTP 读取目录先确认 `CWD` 成功，再执行 `LIST`，避免把无权进入的目录显示为成功的空列表。目录格式兼容性受当前库的 `LIST` 解析器限制：无法解析的行会被库略过，界面可能未显示这些条目，不能承诺所有服务器格式均完整解析。当前 FTP 适配不提供所有者和权限字段。

| 阶段 | 默认边界 |
| --- | --- |
| SSH TCP 建连 | 20 秒 |
| SSH 握手与认证 | 2 分钟；首次主机指纹确认也受初始化时限约束 |
| SFTP 子系统 / 协议初始化及初始目录 | 20 秒 |
| SFTP 单次目录读取 | 20 秒 |
| FTP 建连与登录整体 | 20 秒 |
| FTP 当前目录读取、单次 CWD + LIST | 每次操作 20 秒 |

密码与私钥口令输入本身不设自动超时；存活 SSH 连接不设置闲置超时。SSH 通道创建受调用方上下文与连接所有者管理；底层 SDK 的 `OpenChannel` 没有逐请求 context，取消界面绑定不保证内部等待立即结束。每条连接限制未返回的创建请求，最后有效引用归零后关闭传输以解除等待，不对共享 socket 设置单视图 deadline。
